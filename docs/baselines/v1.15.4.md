## 后续硬预算

- Windows 压缩发布载荷：不超过 150 MiB；单次增长超过 2 MiB 必须提供模块归因。
- onedir 安装体积：不超过 400 MiB。
- 启动：当前 Windows onefile `--help` 与 Web `core_ready` 都不高于 20s，并以官方 Splash 提供真实自解压与入口阶段反馈；最终安装 onedir `--help` 不高于 1.5s 且不装配 Splash；所有门禁都以实测超限阻断；用户确认的协调重启或自动回滚必须在 15s 内完成。
- 首屏 raw HTML + CSS + JS：目标不高于 1.0 MiB；图表、帮助、Lab、Rotation 等非首屏模块延迟加载。实际网络传输预算须在实现压缩与缓存策略后另行建立。
- C901：继续执行 170 的无增长硬上限；只有在真实删除复杂分支后再下调 ratchet，不为达成数字做机械拆函数。
- 架构专项：上述 29 项必须持续通过；新增不可变部署槽、精确 main SHA 激活、失败回滚和开发实例隔离后，补充对应 Windows 集成测试。

## 使用约束

- 当前数值只描述 v1.15.4 重构前基线，不是对未来架构的性能承诺。
- 发布载荷大小与首屏 raw 大小是两种不同预算，不得相互替代。
- 历史 onefile 测量仅用于选择打包方向；任何 onedir 优势都必须由新产物实测确认。
- Windows ACL 首次失败应保留为验证环境证据；不得计入产品回归，也不得通过系统 Python 或未准备的临时目录绕过。
