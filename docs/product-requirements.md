# QuantMaster 产品需求文档

状态：阶段 1 基线
适用版本：v1.15.4 之后的结构重构
产品所有者：个人用户

本文件是 QuantMaster 唯一的产品需求来源。README、指南、架构文档和历史变更记录若与本文件冲突，以本文件为准；技术实现不得自行扩大产品范围。

## 1. 产品定义

QuantMaster 是面向个人投资者的本地优先量化研究与决策记录系统，服务两个同等重要的核心目标：

1. **日常研究与决策**：用可核查的市场、板块、资讯和个股证据形成候选与决策快照。
2. **量化研究与验证**：在统一的数据、因子、模型、回测和审批链中验证策略，再进入模拟观察。

产品不连接券商自动下单，不承诺收益，也不把证据不足的结果包装成正式结论。数据、账本、任务和研究工件默认保存在本机；远程数据源与 AI 仅按用户配置提供取证或推理能力。

### 产品原则

- **可信优先**：正式结果必须满足点时、身份、来源、数值语义和完整性合同；证据不足时明确拒绝。
- **单一路径**：一个用户目标只保留一个主入口。Quant Lab 是正式量化研究入口，重复的旧式研究流程应删除而不是长期兼容。
- **本地优先**：优先复用 StockDB 和现有本地缓存，只为缺失或过期字段访问远端。
- **使用与开发隔离**：稳定实例运行已验证的不可变版本，开发活动不得自动重启、占用或改写稳定实例。
- **模块化单体**：保持一个 monorepo 和一个模块化单体产品，不拆分为独立部署的微服务。
- **轻量交付**：核心包只包含日常运行必需能力；重型模型、开发工具和高级教材按需安装或加载。

## 2. 产品范围

| 市场或资产 | 正式能力 | Sandbox 能力 | 明确边界 |
| --- | --- | --- | --- |
| A 股 | 行情、市场状态、板块、资讯、盘后筛选、候选、个股研究、决策、回测、模拟盘和账本完整闭环 | 允许使用降级数据探索 | 核心市场 |
| 境内交易所 ETF | 行情、分类、轮动、份额/资金证据、研究、回测与候选闭环 | 允许不完整目录或证据预览 | 与 A 股共享正式质量门 |
| 港股 | 正式行情与研究层，包含身份、交易日历、币种、点时和研究工件 | 允许降级研究 | 本阶段不进入自动决策、模拟成交或账户执行闭环 |
| 美股 | 参考行情和全球风险背景 | 可做明确标记的探索 | 不承诺正式研究、决策或交易闭环 |
| 期货 | 参考行情与连续序列研究 | 可做明确标记的探索 | 不视为可交易合约，不进入决策或执行闭环 |

以下不在本阶段范围：券商交易网关、自动实盘下单、微服务拆分、完整多市场交易系统、为旧路由或旧快照继续增加适配层。

## 3. 信息架构与主旅程

产品只保留四个工作区；设置、手册和全局搜索是全局工具，不新增工作区。

### 今日

面向日常研究与决策，按固定顺序提供：

`数据新鲜度 → 市场与板块 → 机会流 → 候选 → 个股证据 → 决策快照`

- 行情、市场温度、市场风格、轮动、ETF 与资讯在同一市场上下文中展示，不再作为互相割裂的一级页面。
- 盘后扫描形成机会流；候选是唯一的研究范围；个股分析从候选上下文打开。
- 正式决策必须保存当时的候选、数据截止、质量、模型版本、贡献和回退原因，不自动下单。

### 研究

Quant Lab 是唯一正式研究入口，流程固定为：

`研究问题与范围 → 数据计划 → 因子/模型候选 → 统一验证 → 回测 → 人工审批 → Shadow/模拟观察`

- 研究湖、Artifact 和任务恢复是内部基础设施，不作为另一套产品流程。
- 因子、模型和策略共享候选、标签、成本、点时与版本合同。
- 密封测试、正式门禁或审批失败时保留拒绝证据，不通过更换指标反复救活同一候选。

### 账户

- “模拟盘”和“真实账户账本”在一个工作区内分栏展示，但存储、动作和状态严格隔离。
- 模拟盘只执行已冻结策略的虚拟撮合；真实账户账本只记录用户确认的成交、现金流和分红。
- 产品内不使用“实盘交易”描述账本能力，避免暗示券商连接或自动执行。

### 运行

- 统一展示数据更新、后台任务、自动化调度、消息通道、诊断、版本和手动应用更新。
- 飞书是完整主通道，支持结构化消息、进度和交互；微信是可选的轻量文本提醒，不复制飞书全部能力。
- 来源配置只在设置中维护，任务操作只在运行工作区维护，资讯内容只在今日工作区查看。

## 4. 结果等级与安全边界

产品只存在两种结果等级：

- **正式**：所有必需证据满足当前合同，可保存为正式研究、回测、决策或模拟输入。
- **Sandbox**：数值可用于探索，但证据不完整。所有页面、导出和 API 必须携带显著等级、缺口与 `formal_eligible=false`；不得晋升 Champion、写入正式决策或触发模拟/真实动作。

不得新增第三种模糊等级，不得静默把 Sandbox 数据解释为正式数据，也不得用当前主数据重写历史事实。旧数据证据不足时保留原始值与不可用原因。

## 5. 稳定使用与手动更新

- 稳定实例必须从版本化、只读的运行制品启动，不直接导入任一开发 worktree 的源码。
- 稳定实例与每个开发任务分别使用独立端口、进程身份、临时目录、缓存和可写数据库；开发测试不得指向稳定实例的数据目录。
- 源码保存、构建、测试、分支切换和 worktree 清理均不得触发稳定实例重载。
- “应用更新”是唯一更新入口。它只接受已通过对应验证门的制品，先完成预检，再原子切换；失败时稳定实例继续运行旧版本。
- 每次应用更新都协调切换 Web、Runtime、调度器和 Compute worker，使所有子进程保持同一
  `build_sha`。StockDB 数据目录位于槽外；其 sidecar 是否跨更新保留由 supervisor 的既有
  所有权合同决定，不能造成新旧应用代码混用。

## 6. 包体与加载策略

- 核心桌面包不包含 CUDA、完整深度学习运行时、浏览器开发依赖或源代码测试工具。
- 高级教材、非当前工作区脚本和重型模型按需加载；首屏不得预加载完整手册、Quant Lab 或轮动实现。
- 构建必须报告核心包体、各可选组件、首屏传输量和工作区资源大小；超过预算即阻断发布，不以功能增加为理由自动抬高基线。

## 7. 量化验收指标

| 类别 | 阶段 1 验收标准 |
| --- | --- |
| 信息架构 | 顶层工作区恰好 4 个；完成日常决策主旅程最多切换 1 次工作区；任一核心动作从当前工作区最多 2 次交互可达 |
| 重复入口 | 正式因子/模型研究只有 Quant Lab 一条入口；来源配置、任务操作和资讯阅读各只有一个权威入口 |
| 市场闭环 | A 股和境内 ETF 的正式主旅程均覆盖数据质量、研究、回测、决策或候选、模拟观察；港股正式输出不出现决策或执行动作 |
| 结果等级 | 100% 正式保存入口拒绝 Sandbox 输入；100% Sandbox 页面、API 和导出显式标记等级与不可晋级原因 |
| 时间与身份 | 正式历史回放中，未来证据、错误市场日历、歧义标的和无有效期 alias 的接受数为 0 |
| 稳定实例 | 连续 8 小时边开发边使用期间，因源码保存、构建、测试或 worktree 操作导致的稳定实例重启、端口冲突和数据目录写入冲突均为 0 |
| 手动更新 | 更新前预检失败不影响旧实例；完整应用成功激活或失败回滚均不超过 15 秒；恢复后的所有子进程报告同一精确 SHA |
| 后台连续性 | 更新前停止接单并有界排空；持久任务不丢失、不重复提交，新生 Compute 不得加载其他 generation 的代码 |
| 启动性能 | Windows onefile `qm --help` 与 Web `core_ready` 都不超过 20 秒，并在自解压期间显示真实状态 Splash；最终安装 onedir `qm --help` 不超过 1.5 秒且不装配 Splash |
| 前端体积 | 初始 raw HTML+CSS+JS 总量不超过 1 MiB；ECharts、完整手册、Lab 与 Rotation 不计入首屏且只按需加载 |
| 桌面包体 | Windows ZIP 不超过 150 MiB；单次增长超过 2 MiB 必须给出模块归因；onedir 安装体不超过 400 MiB |
| 消息通道 | 飞书覆盖全部已支持的结构化通知与任务进度；未启用微信时主流程功能损失为 0，微信不得成为正式结果唯一送达路径 |
| 可恢复性 | 更新、任务或数据写入故障不得删除用户事实数据；故障注入验收中静默改写历史结果和不可恢复数据丢失均为 0 |

## 8. 阶段 1 完成定义

阶段 1 完成必须同时满足：

1. 四工作区及两条核心旅程成为实现、测试和文档的共同边界。
2. 市场/资产范围与正式/Sandbox 权限矩阵有自动化合同测试。
3. 稳定实例与开发 worktree 完成进程、端口、制品和可写状态隔离，并通过 8 小时连续使用验收。
4. 重复产品入口被删除或收口；不存在“新旧两套流程均为推荐”的文档。
5. 包体与加载预算进入构建门禁，结果可追溯到具体组件。
6. 所有用户事实数据在重构前完成备份与恢复演练；无证据的旧数据显式不可用，不被静默迁移为新合同。
