# QuantMaster 数据真实性对抗审查（2026-08-09）

## 审查目标

本次审查针对会影响研究、回测、盘后决策和监控的三类风险：数据口径是否完整，来源证据是否可恢复，以及历史回放是否只使用当时已知的信息。审查采用反例驱动方式，不以“接口返回非空”作为通过条件；只有请求范围、标的范围、单位、复权、交易日历、观测时点和来源链都能验证时，数据才可标记为 `verified`。无法证明的旧缓存与旧快照按新契约明确降级或拒绝，不做静默兼容。

## 已收口的高优先级问题

### 行情与 StockDB

- 公共日线、分钟线、面板和快照接口统一返回 `BarDataEnvelope`，包含 `data`、`quality` 和 `provenance`。正式计算入口会阻止 `unavailable`，正式保存还要求输入证据达到 `verified`。
- StockDB 仍是价格主源；Tushare 只在本地缺少交易日历、单位或复权证明时补证，不会在本地证据可用时整段替换价格。
- StockDB 候选若无法通过逐日单位与复权交叉证明，会保留为降级预览候选并继续尝试后备源；只有所有后备都不可用时才落降级数据，不再提前截断可用的可信链路。
- 请求区间与标的集合都进入质量口径。缺交易日、缺分钟桶、缺标的、混合新旧来源、陈旧逐笔时点、重复行、非有限值、非法 OHLC 关系和负成交量都会降级或拒绝。
- 来源链按区间验证覆盖并持久化。仅在历史尾部写入一天 `verified` 记录，不能再把整段旧缓存升级为可信数据。
- StockDB 全市场摄取不再用上游自身的日期或返回标的数自证完整；证券目录、交易日历和停牌证明必须来自独立、可校验的制品。未知缺失不会被解释为停牌。
- StockDB 未提供可验证上游清单时，来源会记录为 `vendor-declared-unverified`，不再硬编码为 Tushare。HTTP 探针改为服务实际支持的只读查询，不再使用不存在的 `ping` 契约。

### 时点、研究与决策

- 日终信号统一使用上海市场 15:00 截止时点。证券目录、CSI 成分、行业、ETF 元数据、新闻分析和策略部署证据都要求观测时间不晚于对应截止时点。
- 证券目录、停牌清单、行业快照、ETF 日线、ETF 复权因子和正式决策输入改为内容寻址制品；文件身份、内容哈希、逻辑哈希和清单不一致时会拒绝读取。
- Champion 替换、组件版本、验证状态和部署证据按事件冻结。历史查询不会再从当前行读取未来更新后的组件或验证结论。
- 正式决策冻结候选母集、行情质量与来源、行业证据、实际特征输入和组件分数；API、CLI 与自动化使用同一保存前证据流程。
- 行情和外部特征的时间索引必须不晚于信号日上海 15:00；正式历史读取会重新验证 SQLite payload 哈希和冻结 Parquet，旧无证据记录或任一制品损坏都会明确失败。
- 研究湖只发布具有点时证券目录和逐日停牌证明的完整截面。StockDB 局部数据可作为本地部分证据，但远端补缺后仍不完整时不会发布偏样本分区。

### 消息面

三类调度均已有实际来源与内容契约：

| 类别 | 当前来源 | 实际内容 | 正式因子资格 |
| --- | --- | --- | --- |
| 快讯 | 新浪 7×24 | 实时 JSON 摘要 | 否；非官方且原始正文不可恢复 |
| 官方 | 上交所、人民银行 | 公告详情正文与内容寻址原始证据 | 是；正文、发布时间、分析时点和原始证据全部通过后 |
| 定期 | 国家统计局两类 RSS、发改委 | RSS 摘要或详情正文与原始证据 | 是；同上 |

- 抓取水位拆为 committed、pending 和 cursor，未追平窗口、后续页 304、置顶旧条目和非单调排序不会再永久跳过中间新闻。
- 同一来源 ID 的修订会保留旧证据；历史因子要求正文版本和分析结果在目标时点前已经可得。批量情绪面板也按逐条 `availability_at` 入场，15:00:59 会进入下一交易日。
- 正式因子重要度和来源权重在分析事务中冻结，持仓/观察池只改变告警排序；之后修改个性化上下文、来源权重或当前行业映射都不能重写同一历史 `as_of` 结果。
- 正式消息因子必须能从内容寻址 gzip 原始证据恢复，并验证该 raw 与本条 URL、提供方 ID、正文哈希、解析器和解析产物的逐条绑定；同源另一条新闻不能借用 raw 洗白。原始证据的物理删除当前 fail closed 禁用，避免数据库引用悬空。
- 内置官方来源按 source ID 冻结 HTTPS origin，列表、详情、每一跳重定向、归档和逐条绑定使用同一规则；外域、非默认端口及 `file://` 不能被标成官方正文。
- 当前网络环境使用 Clash fake-IP 的 `198.18.0.0/15`。安全检查只对域名 DNS 结果允许该代理网段；IP 字面量、回环、RFC1918、链路本地和云元数据地址仍被拒绝。
- 金十开放平台已作为需授权来源显式登记，但保持禁用；未取得凭据和书面授权前，不绕过授权抓取或把它伪装成可用来源。

## 2026-08-09 实网核验

- 新浪 7×24 返回真实 ID、创建时间、标题和详情链接。
- 上交所、人民银行和发改委列表与详情页面均能解析出发布日期和正文；抓取结果为 `full_article`，并保存列表与详情原始证据。
- 国家统计局两个 RSS 均返回真实条目并解析发布时间；内置 NBS 响应上限单独提高到 8 MiB，以容纳当前约 4.2–4.6 MiB 的官方 Feed，自定义来源仍保持 5 MiB 安全上限。
- StockDB 本地 HTTP 服务能返回真实 A 股日线；探针按同一只读数据契约校验结构和有限正价格。

## 分析能力优先的分层结果

正式保存与交易门不再等同于“能否分析”。新增的显式预览层允许证据不足但数值可用的本地数据参与探索，同时把 `formal_eligible=false`、覆盖率、缺失范围和来源放在结果中：

- StockDB 行情只要请求标的可观测、数值结构有效，即可通过 `analysis_eligible` 参与市场状态、选股预览、自动化收盘分析和 Lab 数据准备；单位、复权或来源链不完整时不会写正式决策或触发执行。
- 研究横截面可用 `preview_date` / `qm data preview` 查看 expected 与 observed 的安全交集；重复和母集外标的会隔离，正式 RAW 分区仍要求 100% 完整证据。
- ETF 可显式选择 `tier=sandbox`，从当前本地证券主表、ETF 元数据/份额和 StockDB 日线生成内存预览；production 缺不可变目录时仍拒绝，preview 不进入 latest/history。
- 消息面 sandbox 接受短样本和不完整窗口，并将新浪快讯按 25% 来源权重纳入探索；production 资格没有放宽。
- 五个现有旧候选池重新可见并可用于当前分析：半导体材料设备 40、沪深300 300、盘后候选 30、科创50 50、科技 4。它们明确标为 `legacy-custom-preview`，不能历史回放或正式落账。

实机以“科技”4 标的运行 StockDB/本地缓存面板，成功计算 2026-08-07 市场状态为“震荡”、多头分 51.17；行情覆盖可分析但来源链、单位/复权、旧候选和旧行业均保持降级。ETF sandbox 从现有本地证据识别 1,629 只产品，母集内覆盖 100%，其中 99.26% 带观测时点，并继续声明它不是完整市场分母。现有新闻库的 sandbox 个股消息面在 10 个请求交易日中有 8 日覆盖、11 个可用事件，并明确标记新浪 25% 权重与不可晋级原因。

## 明确保留的限制

- 金十尚未接入数据适配器。需要开放平台授权和凭据后才能启用；当前状态是“可见但不可用”，不是成功来源。
- 上交所、人民银行、发改委和国家统计局尚无经过验证的分页或历史 cursor。单次窗口容纳不下积压时会保持 `snapshot_window_exhausted/degraded` 且不推进水位，但不能自动修复该缺口。
- 新浪及自定义非官方来源当前只保存内容哈希，不保存可恢复原始字节，因此严格排除在正式可信因子之外。
- 没有目标日盘后不可变证券目录、停牌清单或行业证据时，历史研究与 ETF 回放会 fail closed；不会用今天的主数据猜测过去。
- StockDB 价格可本地优先使用，但若单位或复权因子链没有本地证明且补证源不可用，结果只能用于明确标记的降级预览，不能保存为正式决策。
- 部分实时快照源不提供可验证的交易所时间戳；这种数据不会被冒充为实时证据，依赖它的实时宽度功能会明确降级。

## 验收原则

发布门禁以反例测试为准：旧证据不能因新尾部记录被洗白，部分截面不能因“非空”被视为完整，未来取得的目录、分类、分析和复权信息不能进入历史回放，原始证据损坏或被改写时必须拒绝而不是重算出另一份历史。所有项目测试、静态检查和发布账本会在独立工作树合入最新主线后再次执行。
